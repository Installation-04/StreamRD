# StreamRD and Phosphor v0.23.2 — Converted videos play; the whole product is tested in a real browser

Every video the server converts (MKV, DTS, HEVC and so on) failed in the web player. This release fixes that and several things found while playing through the product from the first account to a finished request.

## Playback (StreamRD)
- **Converted videos start.** The player page started every converted video over and over: each time the server answered with a converted stream, the page asked again. After a few seconds the server refused with *Too many requests, try again later*. Files that play as they are were never affected, which is why this went unseen. It is fixed; a converted video is now requested once. Present since v0.22.0.
- **Resuming and seeking no longer stop some files.** When only the audio needs converting, the picture is copied, and a stream that starts part-way in begins at the nearest earlier keyframe. In many H.264 files (Blu-ray style encodes above all) that keyframe is not a clean starting point, and a browser stops with a decode error where a desktop player carries on. The player now asks the server once to convert the picture as well from that moment, and keeps doing so for the rest of that video. The title bar then reads *Converted for your browser*.
- **A refused stream shows its reason.** When the server refused a converted stream (expired, busy, or a conversion that failed at once) the player showed a black page. It now shows the help box with what the server said. If picture conversion is turned off (`TRANSCODE_VIDEO=false`) and a file needs it, the player says so.
- **No warning over a video that is playing.** A converted video showed "This file may not play in your browser" while it played. The box now appears only when playback fails, or for a file played as it is.
- **Seeking is dependable and lighter.** A quick click or tap on the seek bar could be lost, and each arrow-key press restarted the conversion. One seek is now sent at the end of a drag, or a moment after the last key press. Space, Esc, F, M, J, L and N keep working after a click on the seek bar.
- **Smaller things.** File names in a pack no longer start with a slash; the clock no longer runs past the length; the version and age-rating choosers follow the dark theme.

## Library
- **Titles are no longer left out on import because of their name.** A release whose name ends in an audio codec (`…WEB-DL.H264.AAC`, `…DVDRip.XviD.MP3`, `…x264.FLAC`) was taken for an audio file and skipped without a word. Press **Scan again** on Imports to bring them in. Applies to StreamRD and Phosphor.
- **The scan says what it left out.** Admin → Logs lists the names a scan skipped as not being a film or a show, so a missing title can be traced.

## For viewers
- **A dead link is explained to the person watching.** Pressing Play on a title whose link had stopped working told a viewer to "rescan your private library", which only the administrator can do. A viewer is now told that the link stopped working, that the administrator is informed automatically, and that the title comes back when a replacement arrives. The administrator still gets the instructions meant for them.
- **No more dead ends.** A viewer's Setup page offered "Your private debrid library", which led to a page that answered "Admin role required". That card is gone for viewers, the Imports page takes anyone who is not the administrator to their libraries, and the debrid link on the profile page is shown to the administrator only. Applies to StreamRD and Phosphor.
- **A version whose link stopped working is marked** in the version chooser.
- **Admin → Logs no longer scrolls sideways on a phone**, and the account Settings page no longer shows an empty server address or keeps an old error on screen after you correct the field.

## Who can join, and Plex or Jellyfin (two defaults changed)
- **A server is invitation only unless its administrator opens it.** Until now anyone who could reach the sign-up page could create an account, and then watch every library marked *Visible to everyone*. The first account, which sets the server up, still needs no invitation. Choose **Open registration** in Admin → Users if that is what you want. Applies to StreamRD and Phosphor. See *Upgrading* for what happens to a server that is already running.
- **The helper that starts Plex or Jellyfin is part of every install unless declined.** It was already included on new installs. Running the installer again on an older install now adds it too: with a question when someone is there to answer, without one under `--yes`. `--no-media-manager` removes it and is now remembered, so later runs keep it off until you pass `--media-manager`. A running server cannot add the helper by itself, on purpose: the helper holds the Docker socket and StreamRD never does.

## Setup
- **A new server tells its first visitor what to do.** The home page offered only *Sign in* when nobody had an account yet. It now offers *Create the first account*.
- **A wrong debrid key is explained.** Test connection answered `[realdebrid] bad_token`. It now says the provider did not accept the key and what to do, and tells apart a refused key, a rate limit, a timeout and an outage.

## Logs: one place to follow what happened, and one file to send
Applies to StreamRD and Phosphor.

- **Requests appear in Admin → Logs.** Every step of a media request (received, approved, which release was chosen, submitted, progress, available, failed) is now in the log as type *request*, in order with everything else. Earlier requests are there too: the steps are read from where they were already recorded, so nothing is written twice.
- **Search finds a whole story.** The search box also looks in each entry's details, in request titles and in request ids. Typing a title shows that request from start to finish. Failed steps are *error*; steps needing attention, declined or cancelled are *warn*.
- **Diagnostic bundle.** A new button downloads one file for a bug report: the version and runtime, which settings are set (never their values), the update state, backups, request counts, requests that failed or have been stuck for six hours with their history, and the last seven days of the log. Links are cut down to their host; magnets, e-mail addresses and anything shaped like a key or token are removed. Read it before you share it.
- **More of what the server does is recorded.** Each play (who, which title, and whether it was played as it is, repackaged, or converted, and why), each play that failed and the reason, the end of each account scan with its totals, failed sign-ins, saved debrid settings, failed connection tests, and indexers added or removed. No entry holds a link, a file path or a key.
- **How an update went is in the log.** An update replaces the container, so the server that asked for it never saw the result. At start the server now asks the update helper what it last did and records it once: finished, already current, or failed and rolled back, with the helper's steps in the details.

## What it costs
Converting the picture uses much more processor than copying it and is capped at 1080p. It happens only for files that need it, and for the open-GOP case only after you resume or seek in them.

## Nothing is lost or rewritten
No migration. Two stored values are new: which update was last written to the log, and the registration choice on a server that had never saved one (see *Upgrading*). No account, library, grant or setting you made is changed.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button if you have the helper.

- **Registration.** If you saved a choice in Admin → Users at any time, nothing changes. If you never did, your server was open; on its first start with this version the choice is recorded as **Invitation only**, and Admin → Logs carries a line saying so. Existing accounts, their sessions and their library access are untouched. To let anyone sign up again, choose **Open registration** in Admin → Users.
- **Plex or Jellyfin from the Setup page, and the Update button.** If Setup says the helper is missing, run `bash install.sh` once in your install folder. It keeps your settings and data.
- **Imports.** Press **Scan again** on Imports to bring in titles the old filter skipped.

## Verification
- **The owner's journey, in Google Chrome 153, on every pull request** (`qa/lab/journey.cjs`). The real API, web app and gateway run on one machine against a stand-in debrid account, indexer and metadata source, with real video files. Nineteen steps: the first account; a wrong and a right debrid key; import; matching; two libraries; an MP4 played as it is; an MKV with DTS played with converted audio and requested exactly once; a seek in it that the browser refuses and the player recovers from; resume; HEVC 10-bit with TrueHD and Xvid in AVI; a title still downloading; a season pack through Up next; invitations; a child's account that sees only G-rated titles and is refused the rest by the server; a request from search to release choice to transfer to playback; the request's history in the log; a diagnostic bundle with no key, address or link in it.
- **The journey fails on the old player.** With the one-line cause of the loop put back, it stops at the first converted file with *Too many requests, try again later*, the message a viewer saw.
- Server tests: 55 files and 532 tests for StreamRD, 48 files and 465 for Phosphor. New ones cover the open-GOP case with a decoder as strict as a browser's, the import filter, the connection-test messages, the joined log, redaction, the bundle, the update record and the new log entries.
- Checked by hand in the lab and not yet part of the journey: My List, watched marks and the Unwatched filter, Continue watching, changing a password, signing out and in, deactivating and reactivating a member, raising a child's limit, creating a backup and the restore confirmation, a link that dies (two checks mark it, a title with another version switches to it, a title without one gets a replacement request), and every page at phone width.
- `qa/converted-playback.cjs` checks the conversion route alone in Google Chrome. The conversion tests run in CI for the first time: they used to skip themselves there because ffmpeg was not installed.

Not verified:
- **The helper on a real machine.** The installer's behaviour is covered by its own test with a stand-in for Docker; adding the helper to an existing install and launching Plex or Jellyfin through it were not run here.
- **A real debrid account, indexer or metadata service.** The lab answers as those services are documented to. Behaviour against a live account is established only by using one.
- **Your own failing file.** The loop affected every converted file, so it affected that one; whether anything else is wrong with that file shows only by playing it on this version. If it fails, the help box and Admin → Logs now say what the browser or the server reported.
- **Other browsers and hardware decoding.** Firefox, Safari, Edge and Chrome with GPU decoding were not run.
- **Phosphor in a browser.** Its shared changes (import filter, logs, connection test) are covered by its server tests; its pages were not clicked.
- **The update record against the real helper.** It was tested against a stand-in that answers as the helper does, not during a real container update.
- **Redaction is pattern-based.** It removes what it recognises; read the bundle before you share it.
- A converted stream held paused for 40 seconds through the gateway kept playing; longer pauses were not tried.
