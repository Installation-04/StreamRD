# StreamRD and Phosphor v0.8.0 — Requests, one container, and admin maintenance (shipped in v0.8.1)

This version was merged to `main` and validated, but no `v0.8.0` tag was published. Its changes
ship in [v0.8.1](v0.8.1.md); install that tag.

## Discover and request media
Both web apps can search TMDB/OMDb outside the library, check what a viewer can already
watch, and let them request a title. Requests are deduplicated, viewers follow a shared
request privately, and administrators approve and track them through cloud providers
or a local qBittorrent. See [media-requests.md](https://github.com/Installation-04/StreamRD/blob/main/docs/media-requests.md).
This work was started by Codex and rebased onto v0.7.0 for this release.

## One container
A root `Dockerfile` and `infra/docker-compose.single.yml` run StreamRD, Phosphor and
qBittorrent in one supervised container. See
[single-container.md](https://github.com/Installation-04/StreamRD/blob/main/docs/single-container.md).

The tag also publishes the image to the repository's container registry
(`linux/amd64`, built by GitHub Actions); see
[single-container.md](https://github.com/Installation-04/StreamRD/blob/main/docs/single-container.md#prebuilt-image).

## Admin: updates, backups and restore
**Admin → System** (both products) now has:

- **Check for updates**, comparing against the latest GitHub release (can be disabled).
- **Update**, enabled only when the operator sets `UPDATE_WEBHOOK_URL`: a verified
  backup is taken, then the hook is asked to roll out the new version. The server
  does not replace itself and the hook address cannot be set from the web.
- **Backups & restore**: create, download, verify and delete integrity-checked SQLite
  snapshots; restore needs a typed confirmation, takes a safety backup, and swaps the
  database at the next start (the Compose files let the page restart the service).

See the [admin guide](https://github.com/Installation-04/StreamRD/blob/main/docs/admin-guide.md#updates-backups-and-restore-system-page).
