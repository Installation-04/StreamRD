# StreamRD v0.46.0 — release downloader for programs inside the container

## What changes for you
**Nothing you can see yet.** This is the third step toward running Zurg, Zilean, media servers and library tools inside the StreamRD container (plan: `docs/in-container-services.md`). It adds the part that installs a program by downloading it from GitHub, which the next releases will use for Zurg.

## What was added
A release downloader in the container (`infra/single-container/releases.cjs`):
- It finds the download for this machine among a release's files (Linux, the right processor). If more than one fits, or none, it says so and stops instead of guessing.
- It downloads with a size limit and checks the file against the SHA-256 checksum GitHub publishes for it. A file that does not match is thrown away. When GitHub publishes no checksum, the install says it could not be verified.
- It only talks to GitHub: other addresses, plain http and a redirect to another site are refused.
- It unpacks `.zip` and `.tar.gz` files without letting them write outside their folder: unsafe paths, links, damaged files and archives that would unpack to far more than they should are refused.
- It puts the program in place in one step. The earlier install is kept until the new one is in place, and put back if anything fails, so a failed install never leaves half a program behind.
- It never runs anything it downloads.

## Not done yet
Using it: Zurg and its Real-Debrid mount inside the container come next (rclone will come from the image itself, so it does not need downloading), then Zilean and its database, media servers and library tools, and the guided setup page. New installs will also need the FUSE device and `SYS_ADMIN` for the mount; the installer will add them.

## Nothing is lost or rewritten
No migration, no setting, no change to what runs today.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
Eight tests run it against a stand-in for GitHub and archives made in the test: choosing the download (Zurg-, rclone- and other-style names, several fit, none fit, unknown processor), a good install, the checksum (matching, missing, wrong), replacing an earlier install and putting it back on failure, unsafe archives (`..`, absolute path, links, damaged, too many files, too large), `.tar.gz`, GitHub-only addresses and redirects, and plain reasons for not found, rate limit and offline. **Not verified:** against GitHub itself (this build environment cannot reach its release pages), so the real file names of Zurg's releases have not been checked beyond the naming it expects (`linux` and `amd64` or `arm64`, as DUMB also relies on).
