# StreamRD and Phosphor v0.9.1 — Hardening and stability

A hardening release from the code audit: no new screens, no database migration, nothing to configure.

## Stability
- **SQLite runs in write-ahead-log mode.** The background workers (library scan, metadata, requests) and web requests no longer block each other, which removes occasional "database is locked" stalls. The mode is stored in the database file and is applied at start. Backups (`VACUUM INTO`) and restores already handle it. Set `SQLITE_WAL=false` to keep the old mode, for example when the data folder is on a network file system, where WAL is not safe. The existing 5-second busy timeout is unchanged.

## Security
- **The single container no longer allows cross-origin API calls.** Both web interfaces call their API from the same origin, so `CORS_ORIGINS` now defaults to none there. Set `CORS_ORIGINS` (comma-separated origins) only if you put another web app in front. Split installs keep their configured value.
- **Security headers on every API response** (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`) and, in the single container, on the web pages too (`SAMEORIGIN` framing, same-origin referrer).

## Scale
- Home rows read at most the 2,000 newest titles, the admin catalog list 5,000 titles and the admin user list 5,000 users, instead of loading everything. Exports are unchanged and complete.

## Upgrade
`docker compose pull && docker compose up -d`. No migration; downgrading is safe.

## Verification
Backend: 425 StreamRD and 368 Phosphor tests, including new header, CORS and WAL tests; type checks clean; single-container smoke tests. Not verified: WAL on non-local file systems (documented opt-out), and a Content-Security-Policy, which is not included yet.
