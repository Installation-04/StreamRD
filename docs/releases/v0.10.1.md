# StreamRD and Phosphor v0.10.1 — Sessions the page cannot read

## What changes
In the single container (where each web app and its API share an origin) your sign-in now lives in an **HttpOnly** cookie. Page scripts, and therefore any script injected by a future bug, can no longer read the session token; it is also kept out of the sign-in response and of web storage. Sign out clears it.

Because the browser now sends the cookie by itself, the API also refuses cookie-authenticated changes (anything but reading) that are not from the same site: it checks `Sec-Fetch-Site`, then the request's `Origin` against the host (or the forwarded host behind your trusted proxy, `TRUST_PROXY=true`), or an origin you listed in `CORS_ORIGINS`.

## Who is affected
- **Single container:** nothing to do. Existing sign-ins keep working; the next sign-in switches to the HttpOnly cookie. Behind your own HTTPS proxy, set `TRUST_PROXY=true` so the cookie is marked Secure, and pass the original `Host` header (or `X-Forwarded-Host`).
- **Mobile and TV apps, scripts using Bearer tokens:** unchanged.
- **Split installs where the web app and API are on different origins:** unchanged (token in the sign-in response and a script-readable cookie, as before). Move to the single container to get HttpOnly sessions.

## Upgrade
`docker compose pull && docker compose up -d`. No migration. Downgrading is possible, but see the 0.10.0 note on encrypted credentials.

## Verification
Server tests in both products cover the cookie attributes, the missing token in the response, Secure behind a trusted proxy, cookie authentication, logout and revocation, rotation on password change, and the cross-site guard (cross-site, other-origin, listed origin, legacy same-site, trusted forwarded host; Bearer requests and reads are never blocked). The single-container browser journey signs in through the real UI and asserts an HttpOnly, SameSite=Lax cookie, no readable token in `document.cookie` or web storage, and that signing out clears it. Not verified: your own reverse proxy setups, and any custom client that sent the `X-Session: cookie` header.
