# StreamRD v0.22.0 — Plays everything, finds releases by itself, and tells you what needs fixing

A file like `Crank 2006 Director's Cut 1080p BluRay DTS x264.mkv` used to stop at "No video with supported format and MIME type found". Now it plays.

## It plays in the browser
The server converts a file while you watch, only as much as it has to:

| What the file is | What happens | Cost |
|---|---|---|
| MP4 with H.264 and AAC | Played directly from the provider, as before | none |
| MKV with H.264 and AAC | **Repackaged** into MP4, video and audio untouched | very light |
| DTS, AC3, E-AC3, TrueHD... audio | **Audio converted** to AAC, video untouched | light |
| HEVC, 10-bit, VC-1, XviD... video | **Video re-encoded** to H.264 (capped at 1080p) and audio to AAC | heavy |

- The player says what it did (for example "Audio converted for your browser") and draws its own seek bar for converted videos. Seeking restarts the conversion at the chosen second, so a seek takes a moment. Resume, Continue watching and Up next work as before.
- The server reads the real file first (ffprobe), not just its name, so a mislabelled release still plays. When the file cannot be read it falls back to the name.
- Your browser never gets the provider link for a converted video, only a short-lived, unguessable stream address. ffmpeg runs without a shell, with a protocol allow-list, and is only ever given a public `https` link the server resolved itself.
- **Limits.** `TRANSCODE_MAX` (default 2) videos are converted at once; more get a short "try again". `TRANSCODE=false` turns conversion off; `TRANSCODE_VIDEO=false` keeps the light conversions and never re-encodes video. HDR video is converted to standard colours without tone mapping, so it can look flat; a pure HDR display path still needs VLC or mpv.
- ffmpeg is now part of the image (a larger download, about 100 MB more).

## Tags on every title
The title page shows what the file is as small tags: **resolution** (480p, 720p, 1080p, 4K, 8K), **source** (BluRay, WEB, Remux, HDTV...), **video** (H.264, HEVC, AV1, 10-bit...), **audio** (DTS, DTS-HD, TrueHD, Atmos, AC3, E-AC3, AAC...), **HDR** (Dolby Vision, HDR10, HDR10+, HLG) and the **container** (MKV, MP4...). Library cards carry the resolution. Both products. The tags are read from the release name.

## Watch trailer on the title page
When the public catalogue has a trailer for a matched title, **Watch trailer** opens it in a window. Like the home page, nothing is loaded from YouTube until you press the button, and `HOME_TRAILERS=false` removes it.

## It tells you what needs fixing
- **Cards and title pages show problems.** A broken link shows a red **⚠ Link broken** on the card, and on the title page a banner says a replacement was requested (administrators get **Check again** and a link to the import). For the administrator only, a title whose match needs a decision shows **Review match**, **No match found** or **Match error**, and the title page has **Fix the match**.
- **A summary on every library page (administrator).** "⚠ 2 titles need a match · 1 broken link" with **Show only these**, so the work is one click away. Members never see match problems, only the link state.

## Requests find their own release
Approving a request no longer needs a magnet. **Leave it empty** and StreamRD searches your indexers and picks the best release: **Admin → Request settings → Release search** takes a Torznab URL and key (Prowlarr or Jackett), and Zilean from `install.sh --zilean` is found on its own. It keeps only releases of the requested title (not its sequels, another year, cams or a single episode of a show), and prefers what plays in a browser: 1080p, WEB-DL or BluRay, H.264, AAC, healthy seeders, and a season pack for a show. **Find releases** lists the ranked candidates with their tags so you can pick another one, and a pasted magnet still works. Keys are stored encrypted and never shown again. With no indexer, or nothing found, it says so and asks for a magnet.

## Shows by season
A show with several season packs on the account shows **Seasons** on its title page (Season 1, Season 2, Seasons 1–4...), each with its quality, instead of an anonymous list of versions. One card per show in the library, as before.

## Trailers that work
The title page and the home banner now ask TMDB (when a TMDB key is configured in Admin → Metadata or `TMDB_DEFAULT_API_KEY`) for a trailer the free catalogue does not have, and your own library titles in the banner get their trailer too. The previously missing trailers are mostly this; a title neither source knows still gets **Find trailer**.

## Trailers
- **Find trailer.** When the public catalogue has no trailer for a title, the button opens a YouTube search for it, so there is always a way to see one.
- **Autoplay moved to the administrator.** The checkbox on the banner is gone. **Admin → Overview → Home page → Autoplay trailers in the banner** turns it on for everyone (off by default). People can still press Watch trailer.

## Big screens
Pages grow with the screen instead of staying a narrow column, and everything is a little larger from 2200 px wide (a 27 to 32 inch monitor) and larger again from 3000 px.

## Plex and Jellyfin without the hassle
A **new install includes the small helper by default**, and the installer's menu recommends "start them later from the Setup page", so Plex and Jellyfin start with one click and nothing else. An existing install keeps its choice: the Setup page now shows one copyable command (`bash install.sh --media-manager`) and an "I ran it — check again" button.

## Nothing is lost or rewritten
No migration and no new table (the home option is one row in the settings table). Going back to v0.21.x only stops the conversion, the tags and the new indicators.

## Upgrading
`docker compose pull && docker compose up -d`. A server whose links are on your own network needs `TRANSCODE_ALLOW_PRIVATE_HOSTS=true`.

## Verification
New tests: the tags for real release names (including the Crank file); the choice of conversion for each combination of container, video and audio; ffmpeg's arguments per mode; only public links reach ffmpeg; real ffmpeg against real files served over http: probing, a converted MP4 with AAC audio and untouched H.264 video, re-encoding 10-bit video, starting part-way in, unknown or malformed stream addresses, and the "busy" answer at the limit; the play route answering with a stream address and the real length, and unchanged for a playable file; the trailer lookup (found, cached, none, catalogue down, switched off, not visible); release finding (matching a title and not its sequels, ranking, reading a Torznab feed, the administrator-only indexer settings with keys stored encrypted, listing candidates, approving with no magnet, the plain messages for no indexer or nothing found); seasons read from release names; the TMDB trailer fallback; the attention counts and filter (administrator only, one administrator's titles never counted for another); the home page option (administrator only, validated, kept); the installer (a first install includes the helper, an existing one keeps its choice). Not verified: a very long conversion on a slow processor, a real debrid link, and playback of the converted stream in Safari and Firefox (it is standard fragmented MP4 with H.264 and AAC); the first real play on your server is the true test.
