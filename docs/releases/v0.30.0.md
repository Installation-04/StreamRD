# StreamRD v0.30.0 — Zilean and Zurg by default, on the Add-ons page

## What changes for the owner
- **A new install includes Zilean**, the index of cached torrents that Debrid Media Manager shares, so a request finds its release without a paid indexer. StreamRD uses it by itself (`ZILEAN_URL`). The first import of its lists takes a while and uses some CPU and disk. `--no-zilean` keeps it off.
- **A Real-Debrid token turns Zurg on** in a new install (Linux): the Default install now asks for it (Enter skips), and `--rd-token` alone is enough. Zurg shows your Real-Debrid library as real folders (`movies`, `shows`) under `mnt/zurg`, which Plex and Jellyfin can read (the empty-Plex-folders problem). If the machine cannot do the FUSE mount, a Zurg that was only switched on by the default is skipped with a message and the rest installs; asking for `--zurg` by name still stops with the reason. `--no-zurg` keeps it off.
- **Existing installs are left as they are.** Re-running the installer does not add either one.
- **Add-ons page: a "Search and library files" row** with Zilean and Zurg cards: their state, **Start / Restart / Stop** for the containers the installer made (Zilean with its database, Zurg with its mount, in the right order), **See its log** (opens Admin → Monitor on that program), and, when one is missing, the exact installer command with a copy button.

## Not done yet
Installing Zilean and Zurg from the page with one button (Zilean needs its own database container and Zurg a mount on the host, which a container cannot set up by itself; the installer does it), and a one-click "add my whole library to Plex/Jellyfin" from the Zurg mount (until then, point Plex at `/mnt/zurg/movies` and `/mnt/zurg/shows`).

## Nothing is lost or rewritten
No migration and no new stored data. New API (administrators): `POST /api/admin/addons/services/:service/:action` (`zilean` or `zurg`; `start`, `stop`, `restart`); `GET /api/admin/addons` gains `services`. The Docker helper gains `GET /services` and `POST /services/:name/:action`, limited to the four containers the installer names.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button. That updates StreamRD only; the installer's new defaults apply to installs made from now on, and to an existing one only if you run `install.sh --zilean` (or `--zurg --rd-token …`).

## Verification
- Installer test (no Docker; a stub stands in): a first install has Zilean and its generated database password and no Zurg without a token; `--no-zilean` leaves it out; an existing install is not given Zilean by a re-run and keeps it; a token on a machine that cannot do the mount finishes the install, says Zurg was not set up and writes no Zurg file.
- Helper tests (Docker stand-in): the state of the four containers; start and restart bring the database or Zurg up first, stop takes Zilean or Zurg down first; a service that is not installed is refused with the command that adds it; any other name, action or container is refused and never reaches Docker; the shared secret is required.
- Server tests: the services in the add-ons list with their state, administrators only, the action passed to the helper and logged, bad names refused, "unknown" when Docker control is off.
- The Chrome journey (29 steps) checks that the Zilean and Zurg cards say "Not installed" with their commands.

**Not verified:** a real Zilean or Zurg running (the installer test uses a stub; the compose files are unchanged from v0.9), the FUSE mount and its propagation into Plex on a real host, the first Zilean import, the new default on Docker Desktop (Zurg is skipped there), and Safari and Firefox.
