# StreamRD v0.34.0 — subtitles in the player

## What changes for the viewer
- **A "Subtitles" menu in the player** when the video file has subtitle tracks built in (most `.mkv` files do). Pick a language (named in your own language where the browser knows it, with the track's title, for example "French — Commentary") or **Off**. It works whether the video plays as it is or is converted for your browser.
- Only **text subtitles** (SRT, ASS/SSA, WebVTT, MP4 text) are offered. Picture subtitles (Blu-ray PGS, DVD) are left out: they would have to be burned into the picture.
- Nothing is converted to show subtitles: the server reads only the subtitle track, so it does not use up the "videos converted at once" limit.

## Not done yet
Choosing the **audio track** (language) before or during playing, picture subtitles, subtitle size and colour, and remembering your language between videos.

## Nothing is lost or rewritten
No migration. The play answer's `playback` gains `subtitles` (index, language, title) and `subtitleId`; new `GET /api/stream/:id/subtitles/:track` returns WebVTT for a registered stream (the same unguessable, short-lived id as converted video, so the provider link stays on the server).

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- Server test with real ffmpeg: a file with two subtitle tracks is listed with languages and a title; the second track comes back as WebVTT with its own text; a track that does not exist, a stream that does not exist and a bad number are refused; no conversion is left running.
- Type checks for the four apps and the shared-files check.

**Not verified:** the menu and the subtitles showing in a real browser (no Chrome journey step yet; the lab media has no subtitle track), Safari and Firefox, and large ASS files with heavy styling (styling is dropped in WebVTT).
