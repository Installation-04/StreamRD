# StreamRD and Phosphor v0.10.2 — Metadata with no account

## What changes
Posters, descriptions, genres, cast, runtime and ratings now work **without creating an account or an API key**. When no TMDB or OMDb key is saved, StreamRD and Phosphor use a built-in source instead (Cinemeta, which serves IMDb-linked data), and switch to your own key the moment you save one. You can also pick **Built-in (no account)** as the default provider.

- **Admin → Metadata** now starts with a *Built-in (no account needed)* card with its own *Test connection* button. Your own TMDB or OMDb keys stay optional upgrades.
- **Automatic matching** can be turned on with no key. It stays off by default, so nothing is sent anywhere until you choose.
- **Find media, Retry matching and the match picker** work on a fresh install. The picker has a *Built-in* choice, and an IMDb ID (`tt…`) can be looked up for any title.
- Title pages credit the source ("Metadata from Cinemeta, which serves IMDb-linked data").

## What is sent, and what to expect
Only the title text or IMDb ID being looked up goes to the service, and only when something needs a lookup (a search, a match, a refresh). No accounts, keys, file paths or personal data.

This is a third-party service with no published terms or guarantees for this use, so treat it as a convenient default, not a promise. It is English only, has no content ratings, and its rate limits are unknown (a "too many requests" answer pauses matching for five minutes). In a spot check of 15 titles, all 8 mainstream films and all 3 series were found by name; the 4 misses were obscure short films (the Blender open movies). Those can be matched by pasting their IMDb ID. TMDB (free for non-commercial use) still gives richer artwork and more reliable search.

## Upgrade
`docker compose pull && docker compose up -d`. No migration, and existing settings and matches are untouched. An install that already has a key keeps using it.

## Verification
New tests in both products cover the search and detail mapping, the poster host allow-list, IMDb-ID lookups, runtime and rating parsing, unknown titles, rate limits and bad responses, the fallback rules, and an end-to-end match with no credentials. Four older tests that described "no key means not configured" were rewritten for the new behaviour. The real code was also run against the live service (movies, a long series such as *The Simpsons*, and an ID lookup). Not verified: the service's long-term availability and terms, and the browser journey for the new card (it runs in CI; the journey does not click the built-in test button because its fixture does not stub the service).
