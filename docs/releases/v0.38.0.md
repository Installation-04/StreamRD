# StreamRD v0.38.0 — install Zilean from the Add-ons page

## What changes for the owner
- **An "Install Zilean" button** on Zilean's card (Admin → Add-ons → Search and library files), like the other add-ons. It downloads Zilean and its database, starts them beside StreamRD and shows the steps while it works (it takes a few minutes). If something goes wrong the card says what, and **Try installing Zilean again** is there.
- **StreamRD finds it by itself**: nothing to type and no restart. Request search uses Zilean as soon as it answers; the first import of its lists takes a while, as before.
- The containers are named like the installer's (`zilean`, `zilean-db`), so **Start, Stop, Restart and See its log** on the card work for both ways of installing. A database left behind by an earlier install is reused with its password; nothing is removed or overwritten.
- Needs Docker control (on in new installs) and StreamRD on its own Docker network, which is how the installer sets it up. Otherwise the card says so and keeps the `install.sh --zilean` command.

## Zurg
Zurg is **still the installer's** (`install.sh --zurg --rd-token …`), because it mounts a folder of the machine for Plex and Jellyfin and that needs the host's mount settings. A button that uses the Real-Debrid key already stored on the server is the next step; it is not in this release.

## Nothing is lost or rewritten
No migration and no new stored data. New API (administrators): `POST /api/admin/addons/services/zilean/install`; `GET /api/admin/addons` gains `installable`, `step` and `error` on each service, and a state `installing`. The Docker helper gains `POST /services/zilean/install`, limited to Zilean; `GET /services` gains `jobs`.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- Helper tests against the Docker stand-in: the database and Zilean are created with the installer's names and settings, on StreamRD's network, with one generated password for both; the database starts first; installing again is refused and creates nothing; a database left behind keeps its password and is not recreated; a StreamRD without a network of its own is refused with the reason; other services, wrong methods and a missing token are refused.
- Server tests: administrators only, only Zilean, the card's states (installing with its step, failed with the reason, running); StreamRD finds a Zilean that answers by name only when Docker control is on, remembers the answer for a minute, and lets `ZILEAN_URL` win.

**Not verified:** a real install against a real Docker (the images were not downloaded here), Zilean's first import, and the button in a browser (no Chrome step yet).
