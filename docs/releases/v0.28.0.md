# StreamRD v0.28.0 — Search and request music

## What changes for the owner
With **Lidarr** installed from Admin → Add-ons, **Discover** gets a **Music (albums)** choice next to Movies and shows. Anyone who may request can search an artist and album and press **Request**. Lidarr then adds the album, monitors it, searches the indexers Prowlarr shares with it, and downloads through the qBittorrent it is linked to, into `data/media/music`.

- A result says *Requested* once asked for and *In your library* once Lidarr has every track. Asking again changes nothing.
- The artist is added but left unmonitored apart from the requested album, so asking for one album never pulls in a whole discography.
- No new account: Lidarr looks albums up in its own online catalogue. If that service does not answer, the page says so.
- Without Lidarr running, the choice is not shown, and the server answers "Music needs Lidarr" with a link to where to install it.

## Not done yet
Music requests are not listed on **My requests**, there is no approval step for them, and a finished album is for Lidarr's `music` folder (point Plex or Jellyfin at it). Seerr, Tautulli and Maintainerr setup still waits on a Plex or Jellyfin sign-in.

## Nothing is lost or rewritten
No migration and no stored data: where an album stands is read from Lidarr each time. New API: `GET /api/music/status`, `GET /api/music/search`, `POST /api/music/request` (accounts with a viewing limit are refused, like movie requests).

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- Server tests against a stand-in Lidarr: sign-in required, results shaped and trimmed (an entry without a MusicBrainz id is dropped, Lidarr's key never leaves the server), Lidarr not running, only an album id accepted (no root folder or profile from the caller), the album added once with its artist unmonitored and searched, and asking again monitors it again without adding it twice.
- The Chrome journey picks Music on Discover, searches, sees the album, requests it with one click and sees it marked. The three music answers are played by the test; the server side is covered above and by the next item.
- The real-Docker add-ons check in CI searches the real Lidarr, requests an album through StreamRD, and asks Lidarr whether it is monitored exactly once.

**Not verified:** Lidarr's catalogue on a runner that cannot reach it (the CI check says so and skips rather than fail), a real download and import of an album, Safari and Firefox on the new Discover choice, and Docker Desktop, rootless Docker and Podman.
