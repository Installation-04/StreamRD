# StreamRD and Phosphor v0.10.3 — Built-in search finds more titles

## What changes
The built-in metadata source (no account, no key) answers name searches with loosely related films when it does not know a title, which hid short films such as *Sintel*. When no result is named as you typed it, the search now also asks **Wikidata**, a free public database, for the title's IMDb ID and reads the details from the same built-in source. Matches found this way are listed first. Nothing changes if you use your own TMDB or OMDb key.

- **What is sent:** only the title text, to `www.wikidata.org`, and only when the built-in source is in use and no result matches the typed name. No accounts, keys, file paths or personal data. A title looked up by IMDb ID never goes to Wikidata.
- **If Wikidata is slow or down:** the search returns what the built-in source found, with no error.
- **Operators:** `TMDB_DEFAULT_API_KEY` (new since v0.10.2) lets one server give everyone a TMDB key. The official image contains no key.

## Measured, and not
A live check against both services found *Sintel* (it was missing before) and still did not find *Cosmos Laundromat*, which Wikidata lists under another title. Paste an IMDb ID for such titles. Wikidata's rate limits can pause lookups; results are cached for 15 minutes.

## Upgrade
`docker compose pull && docker compose up -d`. No migration; settings and matches are untouched.

## Verification
New tests in both products (stubbed services, never the network) cover the Wikidata hit and its ordering, that only the title is sent, no use when a result matches exactly or for IMDb IDs, silence on rate limits, bad JSON and unknown titles, and the type filter. Not verified: Wikidata's long-term availability or limits for sustained use.
