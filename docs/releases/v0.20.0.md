# StreamRD and Phosphor v0.20.0 — My List, and Plex and Jellyfin from the Setup page

Two features in one release.

## My List
Favourites left with the catalogue in v0.18.0. They are back, built on the libraries.

- **A heart on every title.** On a library's grid and on a title's page, the heart (or **Add to My List**) saves the title to **your own list**. Nobody else sees or changes it.
- **My List** is in the menu and, in StreamRD, a row on the home page right after Continue watching. The My List page shows everything you saved, newest first, with the same hearts to take things off.
- **Versions share one heart.** A title that exists as a 1080p and a 4K copy is one entry; the list always shows the version the library shows (and follows it if a broken link makes another version the shown one).
- **It respects who can see what.** You can only save titles you can see, and the list only shows titles in libraries you can see now and within your viewing limit. If a library is taken away, its titles leave your list view but stay saved, and come back with access. A kids account keeps a list of what it is allowed to see.
- Up to 500 titles per person. The list goes with the account if the account is removed.

## Plex and Jellyfin from the Setup page
**Setup → Plex or Jellyfin** (Admin → Plex / Jellyfin) now has a place for everything a media server needs, and a **Launch** button that starts the server in a container next to StreamRD, with your libraries and downloads already mapped (read-only).

- **Fields:** the port, the **Plex claim token** (from plex.tv/claim; passed to the container once and never stored), the **Plex token** and the **Jellyfin API key** (stored encrypted, shown only as the last four characters).
- **Buttons:** Launch, Save settings, Stop or Remove, **Test connection** (is it reachable, and was the saved token accepted?) and **Rescan libraries** (asks Plex or Jellyfin to rescan the libraries StreamRD exports; Plex only the ones under `/library`).
- **Show deploy log** on each card: a live log of the launch (image download with progress, container created and started, any Docker error) followed by the server's own output, refreshed while it starts, with **Copy log**. Claim tokens, Plex tokens and Jellyfin API keys are blanked before the log leaves the helper.
- The setup checklist gets an optional step for it.

### How it launches, and why it is opt-in
Starting a container needs the Docker socket, which is root on the machine, and StreamRD never gets it. `install.sh --media-manager` (or option 5 in the installer's Advanced menu) adds a small helper container that does: it can only start, stop and remove `streamrd-jellyfin` and `streamrd-plex`, has no published port, answers only requests carrying a generated secret, and has the image, mounts, user and every other container setting fixed inside it. It runs read-only with all capabilities dropped. Anyone who controls the helper still controls Docker on that machine, so it is off unless you ask for it, and `--no-media-manager` removes it. The Setup page works without it: it saves tokens, tests connections and rescans for a server you started another way.

## Nothing is lost or rewritten
- **My List** adds one table (`LibraryFavorite`, migration `20261115000000_library_favorites`, additive, applied after the usual automatic backup); it starts empty. The retired catalogue's old favourites stay where they were, unused.
- **Plex and Jellyfin** need no migration: the settings use the existing settings table. The helper, its overlay file and its `.env` keys exist only if you turn it on; a plain re-run keeps what you chose. Containers started from Setup are not removed by `--uninstall` (their settings stay under `config/`); the guide says how to remove them.

## Upgrading
`docker compose pull && docker compose up -d`. Both products. Going back to v0.19.x ignores the new table and leaves the helper unused.

## Verification
**My List.** New tests (both products): add, list, flags on a library's items, a title's page and the home rows, and remove; newest-first order and per-person lists; versions as one entry with the shown version listed; a title not shared with someone cannot be saved by them, a revoked library hides entries without deleting them, and they return with access; a title above a viewing limit cannot be saved and is not listed; the 500-title cap; the list removed with the account; and the StreamRD home row. The migration upgrade tests (every earlier checkpoint) and the additive-migration guard pass. The browser journey hearts a title as an invited viewer, finds it on My List, and checks that the administrator's list stays empty. Not verified: a very long list on a slow connection (the list is capped and loaded in one request).

**Plex and Jellyfin.** New tests: the helper against a fake Docker engine (it answers only with the secret; launches from a fixed specification with fixed mounts, user and network and no privileged or host options; passes the claim token once and never repeats it; refuses other names, bad ports and malformed claim tokens; stops and removes only its own containers; reports a failed download or an unreachable Docker plainly; keeps an ordered deploy log per server without the claim token, and shows the container's output with tokens and colours removed, trimmed to the tail); the API (administrator-only; tokens stored encrypted and never returned; the claim token not stored; Plex rescans only the libraries under `/library` with the saved token; rejected tokens, unreachable servers and a missing helper are explained); the installer (the opt-in overlay is locked down, keeps its secret across re-runs, is removed again, and StreamRD's own compose file never mentions the socket); the browser journey saves a Plex token from the page. Not verified: a real Plex or Jellyfin launch on a real Docker host, which no CI here can do; the first real launch on your machine is the true test, and the page shows any Docker error it gets.
