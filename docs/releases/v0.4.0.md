# StreamRD and Phosphor v0.4.0 — Safe Upgrades

Upgrading a community installation now follows a reviewed migration chain, with a
verified snapshot before changes to an existing database. Both apps also gain a
read-only **Admin → System** page for release and database readiness.

## Protect existing installations

- Versioned SQLite SQL replaces production schema push. Exact historical v0.1
  schemas and unmanaged v0.2/v0.3 schemas have explicit adoption paths.
- Existing nonempty databases receive a unique private SQLite snapshot, verified
  for integrity and foreign keys before migration history or application schema
  changes. An already current database is a no-op on restart.
- Independent checks verify bundled SQL/datamodel hashes, ordered migration
  history and structural checkpoints. Unknown schemas, custom objects, altered
  checksums and incomplete/failed histories stop preparation for review.
- Canonical-path upgrade locks prevent competing preparation commands. Startup
  with schema application disabled inspects readiness without adopting history,
  creating locks/backups or initializing a missing database.
- Historical upgrades preserve populated business tables and foreign keys. The
  v0.4.0 business schema matches v0.3.0; the new history makes future changes explicit.

## Understand readiness

The responsive System page reports the installed version, runtime, database
availability, migration state/counts and optional media configuration. It requires
a live administrator session and exposes no credentials, raw database paths or
exception details. Refresh performs inspection only.

Backup policy is clearly distinguished from evidence that your own backup exists.
The new `db:status` and `db:migrate` commands support deliberate server-side
operations. The wiki and detailed upgrade guide document supported baselines,
controlled startup, interrupted adoption, locks and snapshot recovery.

## Verification and downloads

**318 backend tests** pass: 186 StreamRD and 132 Phosphor. Forty new tests cover
historical/current adoption, preservation, drift, checksum/history refusal,
nonmutating inspection, administrator access and future migration behavior.
Production acceptance includes all four image builds, disposable backup/restore
and populated v0.3 adoption checks, plus 14 browser journeys and 20 screenshots.
See the [validation record](https://github.com/Installation-04/StreamRD/blob/v0.4.0/docs/safe-upgrades-validation.md).

Downloads include screenshots, wiki and updated Project HQ/Notion-importable
tracker bundles with SHA-256 checksums. A live Notion page remains blocked by the
missing workspace connection; no automatic synchronization is claimed.

## Upgrade requirements

Stop all writers, retain the previous image, keep your JWT secret stable, and
follow the [upgrade and recovery guide](https://github.com/Installation-04/StreamRD/blob/v0.4.0/docs/database-upgrades.md).
Copy verified snapshots off-host and test restoration. Old root-owned volumes
still require the documented ownership procedure. Do not delete history or mark
arbitrary migrations applied to bypass a refusal.

SQLite remains the supported database. Optional mounted-file symlink exports
retain Plex/Jellyfin compatibility and normal stream URLs work without a mount.
This release does not add live-provider playback validation, native-client builds,
production-load measurements, registry images or credential-at-rest encryption.
