# StreamRD v0.27.0 — Add-ons sign themselves in and Prowlarr is linked to Sonarr, Radarr and Lidarr

## What changes for the owner
Installing Sonarr, Radarr, Lidarr or Prowlarr from Admin → Add-ons used to leave each one to be set up by hand. A minute or two after one is running, StreamRD now:
- **gives it a login** (a made-up password, kept encrypted). **Show login** on its card tells an administrator what to sign in with. An add-on whose login someone already chose is left alone.
- **tells Prowlarr about every Sonarr, Radarr and Lidarr that runs**, so the indexers kept in Prowlarr are sent to them, with no API key copied by hand.
- **offers explicit bundled-client access** on named Docker bridge installations. The owner approves sharing and bundled reachability, then restarts the server to apply the listener change. Authentication remains required; port 8082 stays unpublished. Withdrawal also applies on restart, and existing add-on settings are preserved.
- **connects an owner-approved qBittorrent client** to Sonarr, Radarr and Lidarr when their download-client list is empty. The enabled connection must belong to an active administrator, be explicitly opted into **Allow installed add-ons to use this connection**, and use a URL reachable by those apps. Sharing is off by default. Existing clients are preserved, each app gets its own download category, and completed/failed download removal is disabled.
- **Connect add-ons** runs the check from the page, with a link to download-client settings and distinct feedback for starting apps, local-only client addresses and errors.

It checks again every few minutes, so an add-on started later is picked up, and changes nothing that is already right.
If the owner later chooses a different username in the add-on, subsequent checks preserve that replacement login too.
Manual linking and the background check share one pass when they overlap, avoiding competing generated logins and duplicate links.
Prowlarr links use the addresses that passed StreamRD's connection probe. This
also supports plain Docker installs on the default bridge, where container names
do not resolve; a shared named network can still use its working container names.

## Upgrading
No migration. One stored value, the encrypted logins (`addons.logins`). New API: `GET /api/admin/addons/:addon/login`, `POST /api/admin/addons/link`.
Existing accounts, libraries and add-on settings are preserved; no manual database step is needed.
Existing qBittorrent connections stay private until their owner opts into sharing.
The new setting is stored in the existing connection JSON and does not change
fingerprints used to track pending request transfers. Turning it off prevents new
configurations without revoking copies already kept by add-ons.
Concurrent signups in both products now retry transient SQLite lock failures, with at most three attempts and all access checks repeated inside the transaction.
