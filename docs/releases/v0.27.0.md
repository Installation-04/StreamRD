# StreamRD v0.27.0 — Add-ons sign themselves in and Prowlarr is linked to Sonarr, Radarr and Lidarr

## What changes for the owner
Installing Sonarr, Radarr, Lidarr or Prowlarr from Admin → Add-ons used to leave each one to be set up by hand. A minute or two after one is running, StreamRD now:
- **gives it a login** (a made-up password, kept encrypted). **Show login** on its card tells an administrator what to sign in with. An add-on whose login someone already chose is left alone.
- **tells Prowlarr about every Sonarr, Radarr and Lidarr that runs**, so the indexers kept in Prowlarr are sent to them, with no API key copied by hand.
- **offers explicit bundled-client access** on named Docker bridge installations. The owner approves sharing and bundled reachability, then restarts the server to apply the listener change. Authentication remains required; port 8082 stays unpublished. Withdrawal also applies on restart, and existing add-on settings are preserved.
- **connects an owner-approved qBittorrent client** to Sonarr, Radarr and Lidarr when their download-client list is empty. The enabled connection must belong to an active administrator, be explicitly opted into **Allow installed add-ons to use this connection**, and use a URL reachable by those apps. Sharing is off by default. Existing clients are preserved, each app gets its own download category, and completed/failed download removal is disabled.
- **Connect add-ons** runs the check from the page, with a link to download-client settings and distinct feedback for starting apps, local-only client addresses and errors.

It checks again every few minutes, so an add-on started later is picked up, and changes nothing that is already right.
If the owner later chooses a different username in the add-on, subsequent checks preserve that replacement login too.
Manual linking and the background check share one pass when they overlap, avoiding competing generated logins and duplicate links.
Prowlarr links use the addresses that passed StreamRD's connection probe. This
also supports plain Docker installs on the default bridge, where container names
do not resolve; a shared named network can still use its working container names.

## Not done yet
Root folders, FlareSolverr in Prowlarr, and Bazarr, Seerr, Tautulli and Maintainerr (they keep their own first-run screens). Music search with Lidarr comes after.

## Upgrading
No migration. One stored value, the encrypted logins (`addons.logins`). New API: `GET /api/admin/addons/:addon/login`, `POST /api/admin/addons/link`.
Existing accounts, libraries and add-on settings are preserved; no manual database step is needed.
Existing qBittorrent connections stay private until their owner opts into sharing.
The new setting is stored in the existing connection JSON and does not change
fingerprints used to track pending request transfers. Turning it off prevents new
configurations without revoking copies already kept by add-ons.
Concurrent signups in both products now retry transient SQLite lock failures, with at most three attempts and all access checks repeated inside the transaction.

- Regression coverage for an owner replacing a previously generated login: repeated checks leave the new username and password unchanged.
- Concurrent manual/background linking shares one pass; signup contention retries are bounded and duplicate-account failures are not retried.
- Regression coverage refuses unresolvable container aliases and verifies that the probed addresses are used without creating another application on a second pass. The original HTTP 400 was reproduced against real Prowlarr/Sonarr on Docker's default bridge as a name-resolution failure. Commit `cb41957` passes all ten CI checks, including the corrected real Prowlarr/Sonarr link test ([container run](https://github.com/Installation-04/StreamRD/actions/runs/43432754314)).
- Local backend acceptance: 627 StreamRD tests and 496 Phosphor tests pass; five StreamRD cases are skipped. Both backend typechecks and all four server/web production builds pass, as does shared-source consistency.
- The documented local-lab journey passes all 26 steps in Google Chrome with no page errors, using synthetic providers and generated media. Added response fixtures check manual connection success, local-only client addresses, starting apps, errors and phone-width layout; the owner's sharing opt-in and withdrawal are exercised through the real settings API. These do not establish real download-client compatibility. A separate Chromium run timed out at the seek/fallback check; failure diagnostics now retain the video state and a screenshot.
- The expanded real-Docker check runs Prowlarr with Sonarr, Radarr and Lidarr. It requires exactly one application link for each program, a generated login, rejection of unauthenticated API access, acceptance of its own API key, and an unchanged second pass. This expanded coverage must pass on the release commit before publication.
- The smoke run refuses an existing Prowlarr container, along with the other add-ons, before it creates or removes anything. The refusal was checked with a disposable Docker command stand-in; the application-list check rejects both missing links and duplicates.
- The qBittorrent schema field names were inspected from real Sonarr, Radarr and Lidarr; the separate `tvCategory`, `movieCategory` and `musicCategory` fields are covered by fixtures.
- The real-Docker check now includes qBittorrent connection creation and each program's own connection-test API. It exposes the bundled client to the bridge only inside its disposable fixture; production keeps its local-only default. This new acceptance check must pass in CI before publication.
- Owner-only opt-in, default privacy for legacy connections, unchanged legacy transfer fingerprints, reset behavior and permission withdrawal during a slow response have dedicated regressions in both products where applicable.
