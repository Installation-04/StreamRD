# StreamRD v0.39.0 — install Zurg from the Add-ons page

## What changes for the owner
- **An "Install Zurg" button** on Zurg's card (Admin → Add-ons → Search and library files). It uses **the Real-Debrid key already stored on the server** for your account, so there is nothing to type or paste: it downloads Zurg and rclone, writes Zurg's settings, starts them and mounts your Real-Debrid library as a **movies** and a **shows** folder on the machine, next to StreamRD's settings folder (`mnt/zurg`, the same place the installer uses). The card shows the steps and, if something fails, the reason.
- **Plex and Jellyfin started from the Add-ons page afterwards see that mount** at `/mnt/zurg`, which is what fills their empty folders. One that was started before has to be started again (Add-ons → its card → start) so it is given the mount.
- The containers are the installer's (`zurg`, `zurg-rclone`), so **Start, Stop, Restart and See its log** on the card work for both ways of installing. An existing `zurg/config.yml` (and what you edited in it) is kept, never overwritten.
- The key is written only to `zurg/config.yml` (private to the server, mode 600). It never comes back to the page, and it is not in the log or in any container's settings.
- If there is no Real-Debrid key stored, the button says to connect Real-Debrid first. If the machine cannot do the mount, the card says why and shows the installer command.

## Needs
Docker control (on in new installs), StreamRD on its own Docker network (the installer's layout), and a **Linux machine with FUSE and a shared mount** for the folder. Most Linux servers already have both; Docker Desktop on Windows or Mac does not, and the card then says so.

## Not done yet
StreamRD **itself** reading the mount (the library export that uses `MEDIA_SOURCE_ROOT`) still needs the installer: it has to give StreamRD's own container the folder, which a button inside that container cannot do to itself. Plex and Jellyfin from the page are not affected. Removing Zurg from the page, and a Windows client app, are separate work.

## Nothing is lost or rewritten
No migration. New API (administrators): `POST /api/admin/addons/services/zurg/install` (takes no body; the key is read on the server). The Docker helper's `POST /services/zurg/install` takes `{ "token" }` and is limited to Zurg and Zilean.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- Helper tests against the Docker stand-in: a missing or malformed token (including one with a line break) is refused before anything is created; the installer's images, names, network aliases, files and settings (rshared mount source next to the settings folder, FUSE device, SYS_ADMIN, config mode 600); Zurg starts before its mount; the key is in no container setting and no log; an existing config is kept; a mount that stops is reported with the FUSE advice; Plex and Jellyfin started afterwards are given `/mnt/zurg`; refused without a network of its own.
- Server tests: administrators only; refused with no stored key and nothing asked of the helper; with a key, the helper gets it and the page, the log and the answer never show it.
- Chrome journey: both cards have an Install button.

**Not verified:** a real install against a real Docker and a real Real-Debrid account, the FUSE mount and its propagation on a real host (the stand-in cannot mount), Zurg's filters on a real library, and the button outside the lab.
