# StreamRD v0.35.0 — choose the audio track

## What changes for the viewer
- **An "Audio" menu in the player** when the video file has more than one audio track (for example the original language and a dub, or a commentary). Each track is named by its language, its title and what it is, for example "French (5.1 AC3)".
- Picking a track **continues from the second you are at**, with the other sound. This works for a video that was playing as it is, too: it then plays through the server (the browser cannot switch the audio of a video it plays itself).
- The first track keeps playing exactly as before; only another track is converted to AAC so every browser can play it.

## Not done yet
Remembering your audio and subtitle language between videos, picture subtitles, and subtitle styling.

## Nothing is lost or rewritten
No migration. The play answer's `playback` gains `audioTracks` and `streamId` (replacing the v0.34.0 `subtitleId`, which was never released); new `POST /api/stream/:id/audio` with `{ "track": 0 }` sets the choice for that stream (the same unguessable, short-lived id that converted video uses).

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- Server test with real ffmpeg: a file with two audio tracks is listed with languages, codecs and channels; the first track is copied, and after choosing the second the stream carries it converted to AAC; unknown streams are refused (404) and bad values are refused (400); no conversion is left running.
- Type checks for the four apps and the shared-files check.

**Not verified:** the menu and the switch in a real browser (no Chrome step yet: the lab media has one audio track), Safari and Firefox, and a switch in the middle of a long stream on a slow link.
