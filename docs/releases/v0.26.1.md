# StreamRD v0.26.1 — Firefox playback, seasons and episodes, one-click requests, and fixes

## What changes for the owner
- **Converted video in Firefox no longer stops after a few seconds.** The player was loading up to 90 seconds ahead whatever the video's size, and Firefox gives a video far less memory than Chrome does. When the browser said its memory was full the player gave up. It now keeps ahead only what fits (by seconds and by size), waits for the picture instead of failing, hands the browser the video a megabyte at a time (Firefox returned 50 MB in one read of a large file), reopens the video at the picture if the browser let go of the data under it, and, if the video still stops, tries once more through the plain video element from where it stopped before showing an error.
- **A video that stops now says why in Admin → Logs.** The player tells the server the browser, the kind of problem and how far it got (never a link or a file name), so a report like "it crashed after a few seconds" can be answered from the log and the diagnostic bundle.
- **Plex and Jellyfin list Movies and TV Shows from the first start.** The two folders under `/library/streamrd` (and `/library/phosphor`) were only made when something was exported, so a new Plex showed nothing to choose when adding a library. They are now made empty when Plex or Jellyfin is started or installed.
- **The Plex / Jellyfin page no longer stretches** while one of them is downloading: the cards keep their own height.
- **Seasons of a show are one show.** A show's seasons were grouped by name and year, and one season's release often carries a year where another's does not, so "Show S01 (2022)" and "Show S02" became two shows until the details matched them. A show is now named without a year, and seasons saved the old way are put together the next time the server starts (only the name that groups them changes; nothing is deleted).
- **A season pack lists seasons and episodes.** Opening a pack with several episodes shows a tab for each season and its episodes in order ("Episode 3 · file name"), the one being watched first, instead of one long list of file names. A pack that is not episodes keeps the plain list.
- **Requests work like a request page.** Discover now searches movies and shows together (best of each first; the type menu still narrows it), every result says where it stands for you (in your library, requested, on its way, declined, needs attention), and a result is requested with one click on its card. Opening a title and requesting from there works as before.
- **A request the provider refuses says why.** Every request on one install ended as "Could not confirm submission" with no cause. The provider's answer is now kept in the log, and a refusal (a blocked release, an account that needs premium, a refused address, too many active downloads, a limit, an unreadable magnet link) is shown in plain words and the request can be approved again. A torrent Real-Debrid had just added is removed again if it refuses the file selection, so nothing is left behind in the account. A failure with no answer at all (a timeout, no connection) is still treated as unknown and not submitted again by itself.

## Nothing is lost or rewritten
No migration, no data touched. New API: `POST /api/stream/:id/problem` (the player's report; the stream's own short-lived id is the credential, as for the rest of that route).

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button. The two empty folders are made the next time Plex or Jellyfin is started; run the installer again to make them for a Plex or Jellyfin started by the installer.

## Verification
- Firefox: the converted-video journey now also runs in Firefox in CI, with Firefox's memory for video set small (60 MB, less than the 90 seconds the old player loaded ahead of a Blu-ray rip). The old player (the one in v0.26.0) fails this check within seconds, with the same error box as in the report; the new one plays on for half a minute. This is a stand-in for the reported file, which was not available.
- Server tests: the player's report (accepted only for a stream that exists, only a short fixed vocabulary, nothing that names a file or a link), each kind of provider refusal in plain words and approvable again, a refusal by what the provider said and not by status alone, no answer at all staying unknown, and the Real-Debrid file-selection clean-up.
- Helper and installer tests: Movies and TV Shows exist before anything is exported.
- Server tests: shows named without a year and regrouped once (idempotent), the merged search with its statuses (and one kind failing not hiding the other).
- The owner's journey in Chrome: the season pack shows its tabs and episodes in order, and the friend finds a film with one search and requests it with one click.

**Not verified:** the exact file in the report (a 1080p Blu-ray rip with AC3 audio) in a real Firefox, Safari, and Firefox's own default memory limit (the CI run uses a smaller one on purpose); the Plex and Jellyfin page in Firefox and on a phone (the layout change is a CSS alignment).
