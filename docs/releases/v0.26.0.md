# StreamRD v0.26.0 — Add-ons: install Sonarr, Radarr, Seerr and more from a page

## What changes for the owner
**Admin → Add-ons** is a new page. It lists nine programs that people usually run next to a media server, and installs each with one button:

- **Organise:** Sonarr (TV shows), Radarr (movies), Lidarr (music).
- **Subtitles:** Bazarr.
- **Requests and stats:** Seerr (people request a title with one click), Tautulli (who watched what on Plex).
- **Indexers:** Prowlarr (already installed by default; it now shows here too), FlareSolverr (lets Prowlarr reach indexers behind a browser check).
- **Clean up:** Maintainerr (rules that remove what nobody watches).

Each card has **Install** (you can choose the port first), then **Open**, **Stop**, **Start** and **Remove**, a checkbox for starting again when the machine restarts, *Check for updates* and *Update now*, and a log box that follows the download and the start. They start beside StreamRD, keep their settings in their own folder under `config/` (a removed add-on keeps them, so installing it again picks up where it was), and are made from a fixed specification: Sonarr, Radarr, Lidarr and Bazarr are given StreamRD's `data/` folder with write access because they move and rename what they import; nobody else is. None of them sees the libraries StreamRD exports or Docker's socket. FlareSolverr has no port on the machine; only the other containers reach it.

They are separate programs made by other people (Sonarr, Radarr, Lidarr, Bazarr, Tautulli, Prowlarr: GPL-3.0; Seerr, FlareSolverr, Maintainerr: MIT). None of their code is part of StreamRD; each image is downloaded from its maker when you press Install. See [Add-ons](../add-ons.md).

## Not done yet
Installing an add-on does not yet sign it in or link it to the others. Open it and finish its own first-run screen. Automatic logins and API keys, Prowlarr to Sonarr and Radarr, a download client, and Bazarr and Seerr to their sources are the next release.

## Nothing is lost or rewritten
No migration. One new stored value, the port and start-with-the-machine choice of each add-on (`addons.state`). API additions under `/api/admin/addons`; the update routes under `/api/admin/modules` now accept the new names. An install without Docker control shows what to run and changes nothing.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button. Nothing starts by itself; Prowlarr behaves as before.

## Verification
- Helper tests: every add-on is made from its written-down specification (image, user, folders, whether it gets the data folder and with write access, port or none, start policy), nothing outside the catalog can be named, and the existing Jellyfin, Plex and Prowlarr behaviour is unchanged.
- Server tests: the list, who may use it, the port and start choice kept for next time, nothing but a port and a yes/no passed to the helper (an image, an environment variable or a claim token is refused), names outside the catalog refused however spelled, stop, remove, logs, Prowlarr's removal remembered, and Docker control off.
- The owner's journey in Google Chrome installs Sonarr from the page, follows the download in its log, opens it, stops it, starts it again and removes it.

**Not verified:** the add-ons' real images were not started here (no Docker daemon): image names, ports and the folders each program expects come from each project's published instructions. Starting each on a real Docker daemon is the first thing to check after the release.
