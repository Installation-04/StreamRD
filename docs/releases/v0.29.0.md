# StreamRD v0.29.0 — Monitor every app, update notes in the app, an Apps tab

## What changes for the owner
- **Admin → Monitor.** What each program StreamRD runs has written, in one place, with no terminal: **All apps** merged in time order, StreamRD's event log, the processes inside the container (server, web, qBittorrent, gateway), every add-on and media server (Sonarr, Prowlarr, Plex, Jellyfin…) and, when they exist, Zilean, its database, Zurg and its mount. Live **Follow**, **Filter**, errors in red and warnings in amber, **Copy** and **Download**. Passwords and tokens are hidden before a line leaves the server. It needs Docker control (the installer's default); without it the event log is still shown, with a note saying why.
- **What's new, in the app.** **Admin → System → Updates** lists what changed and what was corrected in every release after the one you run, newest first, as plain text, and what changed in your own version once you are up to date. No more opening the release page. It uses the same release page the update check already asks, and nothing is fetched when update checks are off.
- **An Apps tab** in the top bar (administrators) that opens the add-ons. It is lit on its own pages, and Admin is not lit there.
- **A title whose link is broken is hidden from viewers**: from lists, counts, its page and playback. It comes back by itself when the link works again or a replacement arrives. You still find it, with the reason, in **Imports → Needs attention**.
- **Firefox streaming.** A report showed Firefox refusing the browser's streaming path for some H.264 movies and then failing on the plain video tag. The player now tries close variants of the declared H.264 level when the browser says no, and the log names exactly what was refused. See "Not verified".

## Not done yet
Zilean and Zurg as add-ons, and on by default (they are installer options today; the Monitor shows them if you run them); Plex-style show and movie pages; season choice when requesting a show.

## Nothing is lost or rewritten
No migration and no new stored data. New API (administrators): `GET /api/admin/monitor/sources`, `GET /api/admin/monitor/logs`, `GET /api/admin/system/update/notes`. The Docker helper gains read-only `GET /logs/sources` and `GET /logs/read`, limited to containers StreamRD runs.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- Helper tests (against a Docker stand-in): StreamRD's own output split by process, a service container, merging for the all view in time order, tokens and passwords blanked (including bearer headers), a tail, and every name outside the list refused (another container, path tricks, odd spellings).
- Server tests: the monitor's sources and logs (labels and groups, not-installed left out, the merge with the event log, administrators only, bad names refused before they reach the helper, Docker control off); release notes parsed into plain sections (markup characters stripped, a script tag kept as text), only the installed version and later ones listed newest first, drafts and pre-releases left out, nothing fetched when checks are off; a viewer no longer sees a title with a broken link in lists, counts, its page or playback, and sees it again when the link recovers.
- The Chrome journey (28 steps) opens the Monitor, filters the event log and downloads it; shows the update notes in the Updates panel as plain text, newest first; checks the Apps tab for the owner (lit on its own page) and its absence for a friend.
- The Firefox rule (accepting close H.264 levels) was checked for its choices in isolation; the Firefox journey in CI is the end-to-end check.

**Not verified:** reading real Zilean, Zurg or rclone containers (none ran in these checks; they are read the same way as the add-ons), the Firefox change against the file in the report (no Firefox ran here, and the plain-tag network error after a skip is not changed), Safari, and Docker Desktop, rootless Docker and Podman.
