# StreamRD v0.43.0 — first step toward services inside the StreamRD container

## What changes for you
**Nothing you can see yet.** This release adds the foundation for running Zurg, Zilean, media servers and library tools inside the StreamRD container itself (one container, one port), instead of as separate containers started through Docker. Every existing install, button and setting works as before.

## Why
Programs that share one container see the same files and the same Real-Debrid mount with no Docker socket and no mount-sharing settings. That fixes the gaps the Install Zurg button has today (StreamRD's own container reading the mount, Plex and Jellyfin needing a restart). The plan, with the order of the next releases, is in `docs/in-container-services.md`.

## What was added
A service supervisor (`infra/single-container/supervisor.cjs`): it starts programs in the order their dependencies need, waits until each answers before counting it as running, restarts one that stops by itself a limited number of times, stops dependents first, and keeps a log of each with secrets hidden. It is not started by the container yet.

The design follows the idea of the all-in-one DUMB project. That project is GPL-3.0 and StreamRD is MIT, so **no code was copied**.

## Not done yet
Everything that uses it: the release downloader, Zurg and the rclone mount inside the container, Zilean, media servers, library tools and the guided setup page. New installs will also need the FUSE device and `SYS_ADMIN` for the mount; the installer will add them.

## Nothing is lost or rewritten
No migration, no setting, no API change.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
Eight tests run the supervisor against small real programs: start and stop order, missing dependency and cycle refused, waiting for a program to answer, restart limit and the reason shown, no restart after a deliberate stop, secrets hidden in logs, a program that ignores the stop request being killed, bad definitions refused. **Not verified:** inside the real container image (it is not used there yet).
