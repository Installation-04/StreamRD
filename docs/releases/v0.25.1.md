# StreamRD and Phosphor v0.25.1 — Prowlarr, Jellyfin and Plex can be updated from the page, without waiting for a StreamRD release

## What changes for the owner
The programs StreamRD starts next to itself (Prowlarr, Jellyfin, Plex) have their own releases. Until now a running one never got newer: its image was downloaded once, when it was first started, and a StreamRD release did not change that. They are now checked and updated from **Admin → System → Add-ons** (and from a small panel in each module's own card: Admin → Library for Jellyfin and Plex, Admin → Request settings for Prowlarr), with Docker control on, the installer's default.

- **Check for updates** downloads the image the module is started from (nothing is downloaded again when it has not changed) and says whether it is newer than the one running, with the version when the image reports one. Nothing is changed and nothing restarts.
- **Update now** does the check and, when there is a newer image, restarts the module on it, in about a minute. The port, the folders under `config/` and whether the module starts with the machine stay as they were. The old container is kept until the new one is running, and put back, still running, if the new one does not start; the page then says so, and the module's log box tells the story.
- **Update by itself at night** is a switch for each module, **off until you turn it on**: it checks and updates between 03:00 and 05:00 in the server's time zone, once a night, only a module that is running. It is off by default because an update restarts the module and a media server stops whatever it is playing; Prowlarr can safely be left to update itself.

The helper decides nothing about the image: it downloads what the module's fixed reference points to now, and makes the container again from the same fixed specification the first start used (the specification is not read back from the old container). A check or an update of a module that was never started, or an update of one that is stopped, is refused in plain words.

## What an update cannot undo
A new version of a program can change its own database in a way an older version cannot read. Putting the previous version back covers a version that does not start; it does not undo a change a version made to its own settings. If the matches and watched marks in Plex or Jellyfin matter to you, keep a copy of that module's folder under `config/` before updating, as you would before updating it by hand. The StreamRD backups on Admin → System cover StreamRD's own database, not those folders. This is written on the page and in [the guide](../plex-jellyfin.md#updating-prowlarr-jellyfin-and-plex).

## Nothing is lost or rewritten
No migration. New stored values: each module's night-update switch and what the last check found (`modules.state`), and the day the night update last ran. API additions: `/api/admin/modules` (list, check, update, night switch). An install without Docker control shows what to do instead (`docker compose pull` and `docker compose up -d`, as before) and changes nothing.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button. Modules already running keep running; the first **Check for updates** downloads their current images if they have moved.

## Verification
- Helper tests: a check finds a newer image and changes nothing; an update makes the container again from the newer image with the same port, folders, network and start-with-the-machine choice and removes the old one once the new one runs; a new container that does not start is replaced by the previous one, still running and set as before (and a later update goes through); a module that was never started, a stopped one, a failed download, a bad request and a missing secret are each answered plainly and leave a running module alone. The rollback test was checked to fail when the rollback is disabled.
- Server tests, StreamRD and Phosphor: the module list and what it asks the helper, the outcome kept after the helper forgets it and recorded once however often the page asks, the update and the night switch (administrators only), Docker control off, and the night run (inside its window only, once a night, only modules set to it and running, and a night the helper cannot be reached is not used up).
- The owner's journey in Google Chrome now also checks Jellyfin from the System page (it finds the newer version and changes nothing), updates it, and asserts that it is up to date on the new version, that "keep it from starting with the machine" survived, and that the log box tells the story.
- The check against a real Docker daemon in CI now also runs Prowlarr from a stand-in older image (the real program with one extra label), checks that a check finds the real image as newer and changes nothing, updates it, and asserts that the old container is gone, the new one runs the real image with only its own folder and answers to StreamRD, and that its settings (its API key) are the same.

**Not verified:** updating Jellyfin or Plex on a real Docker daemon (they use the same code as Prowlarr, which is updated for real in CI, but no real Jellyfin or Plex was updated), the night update over a real night, Docker Desktop, rootless Docker and Podman, and a module image that reports no version (the page then shows when the image was built, or says the version is not reported).
