# StreamRD v0.28.3 — Approve or decline a request in one click

## What changes for the administrator
On **Admin → Media requests**, a request that is waiting now shows **Approve** and **Decline** right on its card. **Approve** uses the cloud destination with the server's automatic release search, as before; if no cloud provider is set up it says so, and **Choose release…** (the old Review request) is still there for picking the release, the destination, or a shared library by hand. **Decline** declines it with the standard message. Servers that approve requests automatically (the default) are unchanged.

## Not done yet
Choosing seasons when requesting a show (requests stay one per show).

## Nothing is lost or rewritten
Web only. The buttons call the approve and decline routes that were already there; no migration, no new stored data.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- The Chrome journey (with automatic approval off) checks that a waiting request shows Approve and Decline on its card, then goes on through Choose release… to the automatic release search, the transfer and the library as before. The one-click buttons themselves use the routes the old form used, which have their own server tests; pressing them was not part of the journey.

**Not verified:** pressing Approve or Decline from the card in a browser, a server with only local (qBittorrent) downloads (Approve says cloud is not set up; use Choose release…), Safari and Firefox, and Docker Desktop, rootless Docker and Podman.
