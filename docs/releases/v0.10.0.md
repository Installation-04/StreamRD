# StreamRD and Phosphor v0.10.0 — Credentials encrypted at rest

## What changes
Stored credentials are now encrypted in the databases with AES-256-GCM:
- debrid keys in both products (Real-Debrid, AllDebrid, Premiumize, TorBox),
- Phosphor's indexer API keys,
- the qBittorrent connection password (Admin → Download settings).

A copied database or backup no longer reveals them. The apps read and write them exactly as before; nothing in the interface changes.

## Upgrade
`docker compose pull && docker compose up -d`. On first start the apps encrypt any plaintext credentials left by earlier versions (once, logged as a system event). The single container generates the keys in `config/secrets/` (`streamrd-data-key`, `phosphor-data-key`). Split installs can set `DATA_ENCRYPTION_KEY`; without it the key is derived from `JWT_SECRET`, so changing `JWT_SECRET` means re-entering the credentials.

**Keep `config/secrets` with your backups.** A backup restored without its key reads those credentials as "not configured" and you enter them again. Downgrading to 0.9.x is not supported once credentials are encrypted: restore a pre-update backup instead (each update takes one).

## Not included
Browser sessions are still stored by the web apps as before; moving them to HttpOnly cookies ships separately (v0.10.1). Passwords were already hashed, and invitation tokens were already stored as hashes.

## Verification
New tests in both products cover the encryption round trip, tamper rejection, encrypted storage, transactions, the one-time migration of plaintext values and the indexer and qBittorrent secrets. The single-container smoke test checks the new key files exist and are private (0600). Not verified: restoring across hosts with a different key (the behaviour above is by design), and behaviour on databases I have not seen.
