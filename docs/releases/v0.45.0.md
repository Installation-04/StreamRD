# StreamRD v0.45.0 — programs inside the container show up in the Monitor

## What changes for you
**Nothing you can see yet**, because no program is run this way yet. This is the second step toward running Zurg, Zilean, media servers and library tools inside the StreamRD container (plan: `docs/in-container-services.md`). When the first one arrives, it will appear in **Admin → Monitor** under *Services* with its state and its log, and can be started, stopped and restarted.

## What was added
- The Docker helper now holds the service supervisor from v0.43.0 and offers it to the server: list the programs and their state, start, stop or restart one (starting one starts what it needs first, stopping one stops what depends on it first), and read each one's log with secrets hidden.
- Admin → Monitor lists those programs and can show their logs.
- **They never run as root.** The helper itself runs as root inside the container so it can reach Docker, so every program it starts is given the container's unprivileged user and group unless its definition explicitly asks for root (the Real-Debrid mount will need that one).
- When the container is told to stop, these programs are stopped first, in dependency order.
- `supervisor.cjs` is now copied into the image next to the helper.

## Not done yet
Registering real programs (the release downloader, Zurg and its mount, Zilean and its database, media servers and the rest) and the guided setup page.

## Nothing is lost or rewritten
No migration, no setting, no change to what runs today. Existing Docker-based installs and their logs are listed exactly as before.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button.

## Verification
- Helper tests: listing, start, stop and restart in dependency order, unknown names (404), wrong method (405), no token (401), log with secrets hidden, source list; user and group given to a program, root only when asked, an explicit user kept.
- Server tests: Monitor labels a supervised program, leaves out one without a name, and accepts its log source.
- **Not verified:** inside the real container image beyond the build and the Chrome journey (no program is registered, so nothing exercises it), and stopping programs on a real `docker stop`.
