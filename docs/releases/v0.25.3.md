# StreamRD v0.25.3 — Phosphor is off by default

## What changes for the owner
A new install now runs StreamRD alone, with the download client. Phosphor (the indexer search and download companion, port 8081) is not started unless you ask for it:

- **New install:** `install.sh --phosphor` runs it too. In the installer's questions, "Run Phosphor too?" now defaults to no, and the Zilean question only appears when Phosphor is on.
- **Later:** run `install.sh --phosphor` again to turn it on, or `install.sh --no-phosphor` to turn it off. Its data is kept either way. By hand: `ENABLE_PHOSPHOR=true` in `~/streamrd/.env`, then `docker compose up -d`.
- **Already running Phosphor?** Nothing changes for you. Your installation keeps running it, including after `install.sh --refresh-compose`.

Port 8081 is still reserved in the container definition, so turning Phosphor on later needs no other change.

## Nothing is lost or rewritten
No migration and no data is touched. `ENABLE_PHOSPHOR` is written to `.env` (`false` on a new install, `true` on an install that did not have it, so it keeps what it was running). In the container, an empty or missing `ENABLE_PHOSPHOR` means "on only if this configuration folder already holds Phosphor's data"; `true` and `false` mean what they say.

## Upgrading
`docker compose pull && docker compose up -d`, or the **Update** button. Phosphor stays as it is.

## Verification
- Installer tests: a new install records `false`; a plain re-run keeps it; `--phosphor` turns it on and a plain re-run keeps that; `--no-phosphor` turns it off; an install that predates this and has nothing about Phosphor in `.env` is recorded as running it, also after its container definition is written again. Both choices were checked to fail when the install-time default is reversed.
- The container's start-up logic ran with every combination of the setting (not set, empty, `true`, `false`) on a new folder and on one with Phosphor's data, and opened port 8081 only when expected.
- The real-container check in CI now also starts the image with nothing set on the same volumes (Phosphor still answers), and on new volumes (StreamRD answers, nothing listens on 8081, no Phosphor data is created).

**Not verified:** the installer's question screens were run in a terminal here, but the full real-container check ran only in CI.
