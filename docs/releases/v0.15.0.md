# StreamRD and Phosphor v0.15.0 — Invitation links that carry library access

## What changes
Inviting someone now sets them up in one step. In **Admin → Users → Invite someone**, besides the email address you choose:

- **Libraries they can watch.** Tick the libraries the new person should get (all of yours are ticked to start; untick any). When they create their account they are given exactly those, and nothing else.
- **Viewing limit.** Optionally start them as a Kids, Pre-teens, Teens or Mature account (see v0.14.0), so a child's account is safe from the first sign-in.
- **Address for invitation links.** Save how invited people reach your server: a local network address (for example `http://192.168.1.20:8080`), its Tailscale name, or a domain. Invitation links then use that address, wherever you happen to be browsing from, so a link made while you were on `localhost` still works for someone else. Leave it empty to use the address of the page.

The person who opens the link sees what they will get ("You will be able to watch: Movies, TV Shows") before they choose a password. The Recent invitations list shows what each invitation grants. Everything else about invitations is unchanged: one use, tied to one email address, expiring, revocable, and the link secret is stored only as a hash.

Because the link is just an address on your own network, this works exactly the same on your local network or over a private network such as Tailscale: anyone who can reach the server can open it and create a local account.

## Safety
You can only hand out libraries you manage. A library deleted before the invitation is used is skipped. The invitation's access is applied in the same step that creates the account, after the invitation is consumed, so a link cannot be reused for more access.

## Upgrading
`docker compose pull && docker compose up -d`. Two additive columns on invitations; existing invitations carry no access and behave exactly as before. Nothing is deleted.

## Verification
New tests (both products): access applied to the new account and no other, the pre-signup preview showing only library names, plain invitations unchanged, refusal of libraries you do not manage and of viewing limits that are not offered, deleted libraries skipped, single use, and the saved link address (accepted forms, rejected forms, administrators only). The migration upgrade tests pass. The invitation form was rendered in a browser and reviewed. Not verified: an invitation delivered across a real Tailscale network (the server only produces the link; it has no knowledge of your network).
