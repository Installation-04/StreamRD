# StreamRD v0.27.1 — Add-ons get root folders, Prowlarr gets FlareSolverr, Bazarr finds Sonarr and Radarr

## What changes for the owner
- **Sonarr, Radarr and Lidarr are given a place to put what they import** when they have none: `data/media/tv`, `data/media/movies` and `data/media/music`, made first. A root folder someone added is left alone.
- **Prowlarr is told about FlareSolverr** when it runs, as a proxy under the tag `flaresolverr`. Give that tag to an indexer that sits behind a browser check.
- **Bazarr is pointed at Sonarr and Radarr** (address, port, API key) when it has none for them, and turns them on. A source someone filled in is left alone.

## Not done yet
Seerr, Tautulli and Maintainerr keep their own first-run screens: they need a sign-in to Plex or Jellyfin, which StreamRD does not hold. Music search with Lidarr comes after.

## Nothing is lost or rewritten
No migration. Existing root folders and proxies are never changed.

## Verification
- Server tests against stand-ins: a folder made and added once, one someone added left alone and nothing made, Lidarr's profiles used, FlareSolverr added once under its tag.
- The real-Docker add-ons check in CI now also asks the real Sonarr, Radarr and Lidarr for their root folder.

- Bazarr: stand-in tests for the settings call (made once, a filled-in source kept) and for reading its key; the real-Docker check asks the real Bazarr for its Sonarr and Radarr settings.

**Not verified:** Bazarr's settings call and key file on a version other than the one in CI; FlareSolverr's proxy record against the real Prowlarr (the same code path as the application links, not run), and an import into the new folders.
