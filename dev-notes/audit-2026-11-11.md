# Audit of StreamRD and Phosphor at v0.23.1 (2026-11-11)

Scope: the repository at `main` (v0.23.1) plus the playback fix in v0.23.2. Each section gives what the code does today, what mature
projects do, the gap with a severity and user impact, and the plan with a size (S = days, M = one to two weeks, L = several weeks) and
whether it needs a migration.

**How far this audit goes.** Read in full: `server/src/transcode.ts`, `routes/stream.ts`, `app.ts`, `http.ts`, `config.ts`, `crypto.ts`,
`auth/middleware.ts`, `util/rateLimit.ts`, the play route in `routes/shared-libraries.ts`, `web/src/components/SharedPlayer.tsx`,
`PlaybackHelp.tsx`, `lib/playback.ts`, `infra/single-container/start.cjs`, `Dockerfile`, `ci.yml`, `RELEASING.md`, `CONTRIBUTING.md`.
Read by search and by excerpt: every other file under `server/src`, the Prisma schema, the other workflows, the web app. Sections that rest
on excerpts say so. Playback was tested in a browser; nothing else in this audit was exercised beyond the existing test suites
(522 StreamRD tests and 456 Phosphor tests pass).

Rule for copying: designs, behaviours, data models and public protocols may be followed. No source code is copied from GPL, AGPL or
proprietary projects. New dependencies must be MIT, BSD, ISC or Apache-2.0.

## A. Playback and transcoding

**Today.**
- Decision: `decideMode` (`server/src/transcode.ts:65`) compares the probed codecs with two fixed sets, `BROWSER_VIDEO` and
  `BROWSER_AUDIO` (`:63`), and returns `direct`, `remux`, `audio` or `video`. When ffprobe fails, `guessMode` (`:75`) reads the file name.
  The client sends nothing about itself.
- Delivery: `streamConverted` (`:139`) pipes one ffmpeg process to the response as fragmented MP4 with `Accept-Ranges: none`. Seeking is a
  new request with `?start=`; the player draws its own seek bar from the probed duration (`web/src/components/SharedPlayer.tsx`).
- Streams: an in-memory map of up to 500 ids that last 12 hours (`:97`); a global limit `TRANSCODE_MAX`, default 2 (`:23`); the newest
  request for an id replaces the older one.
- Tracks: `-map 0:v:0 -map 0:a:0? -sn -dn` (`:112`). The first audio track only, no subtitles.
- Encoding: software `libx264 -preset veryfast -crf 23`, capped at 1920 wide (`:113`). Audio is always stereo AAC at 192 kbit/s.
- The gateway closes an upstream socket idle for 30 seconds (`infra/single-container/start.cjs`, `proxy`). A 40-second pause was tested
  and survived; longer pauses on larger files were not.
- Tests: `server/tests/transcode.test.ts` uses real ffmpeg, which CI did not install before v0.23.2, so those tests skipped themselves.

**Best practice.**
- Jellyfin chooses between direct play, direct stream and transcode from a device profile the client sends, and logs the reason:
  <https://jellyfin.org/docs/general/clients/codec-support/> and <https://jellyfin.org/docs/general/server/transcoding/>.
- Jellyfin and Plex deliver converted video as HLS with segments made on demand, a playlist that states the full duration, a throttle so
  the encoder stays a bounded distance ahead of the viewer, and a transcode folder that is cleaned up.
  HLS with fragmented MP4 segments: <https://datatracker.ietf.org/doc/html/rfc8216> and <https://ffmpeg.org/ffmpeg-formats.html#hls-2>.
- Browsers report what they decode through `MediaCapabilities.decodingInfo`:
  <https://developer.mozilla.org/en-US/docs/Web/API/MediaCapabilities/decodingInfo>.
- Hardware acceleration in Jellyfin (VAAPI, QSV, NVENC) and tone mapping:
  <https://jellyfin.org/docs/general/administration/hardware-acceleration/>.

**Gap.**
| Gap | Severity | Impact |
|---|---|---|
| Copied open-GOP H.264 fails on resume and seek. Reproduced in Chrome; see `docs/playback-investigation.md` | critical | The video stops with no reason. v0.23.2 falls back to re-encoding, which is correct and expensive |
| A refused stream raised its error where the player did not listen | high | A black page. Fixed in v0.23.2 |
| Seeking restarts ffmpeg and reconnects to the provider | high | Each seek costs seconds; nothing already watched can be replayed without converting again |
| No subtitles, one audio track | high | Foreign-language films and multi-language releases are not usable |
| Fixed codec list | medium | HEVC is always re-encoded even where the browser decodes it; a browser without a listed codec gets a stream it cannot play |
| 5.1 audio always downmixed | low | No surround even where the browser supports it |
| No hardware acceleration or tone mapping | medium | 4K and HDR sources need a strong processor and look washed out |
| One global limit, no per-user limit, no list of running streams | medium | One viewer can use every conversion slot; the administrator cannot see or stop streams |
| Stream ids live in process memory | low | A restart ends every running stream |

**Plan.**
1. v0.23.2 (done, PR 60): fallback on decode error, `<source>` errors, ffmpeg and a Chrome check in CI. S, no migration.
2. Client profile and decision module with a logged reason. Copy the idea of Jellyfin's device profile; do not copy its profile format.
   M, no migration.
3. HLS sessions: fMP4 segments of 4 to 6 seconds, a playlist with every segment listed from the probed duration and keyframe positions,
   segments produced on demand with look-ahead, a per-session folder with a size cap, cleanup on idle and stop. Seeking a copied picture
   starts on a segment boundary; where the boundary is not a clean entry point only the first group of pictures is re-encoded. L, no migration.
4. Player on `hls.js` (Apache-2.0) with native HLS on Safari. M.
5. Audio-track menu; text subtitles extracted to WebVTT; image subtitles burned in only when chosen. M.
6. Hardware acceleration detected at start (VAAPI, QSV, NVENC) with a software fallback, and tone mapping for HDR sources. M.
   Cannot be verified without the hardware; ship behind a setting, off by default.
7. Sessions: per-user limit, now-playing list, stop action. S, no migration (in memory) or one additive table if history is wanted.
8. A codec matrix in CI on Google Chrome; Firefox through Playwright; Safari and Edge as recorded manual runs.

## B. Library model

**Today.** `AccountMedia` (`server/prisma/schema.prisma:234`) is one row per imported torrent or file, grouped into cards by `groupKey`
with one primary version. Season packs are versions of one title; the player lists a pack's files and plays the next one
(`SharedPlayer.tsx`, "Up next"). Watch state is `SharedLibraryProgress` keyed by user, item and `mediaKey`. Release names are parsed in
three places: `media-tags.ts`, `versions.ts` and `requests/finder.ts`. Retired tables are kept and unused (`Title`, `Favorite`,
`Profile`, `PlaybackProgress`, `PlaybackLog`, `PlaybackSourceJob`, `PlaybackSession`). `docs/library-model.md` already describes the
remaining data-model work.

**Best practice.** Plex and Jellyfin store show, season and episode as separate records with external ids, attach one or more files to
each movie or episode, and keep watch state per user and episode; "Next up" is derived from it:
<https://jellyfin.org/docs/general/server/media/shows/>. Sonarr and Radarr parse release names in one tested module:
<https://wiki.servarr.com/sonarr> and <https://wiki.servarr.com/radarr>.

**Gap.**
| Gap | Severity | Impact |
|---|---|---|
| No episode records | high | No per-episode watched marks, no "Next up" across a series, no per-season requests |
| Three release-name parsers | medium | The same name can be read differently when importing, grouping and searching |
| No collections | low | Franchises are not grouped |

**Plan.** One parser module with a corpus of at least 500 names (M, no migration). Then additive tables `Show`, `Season`, `Episode`,
`MediaFile` with external ids; dual-write for one release, back-fill, switch reads, keep the old columns (L, additive migration with an
upgrade checkpoint). Then per-episode state and "Next up" (M), collections (S, additive), and one fix-match, merge and split tool (M).

## C. Requests and acquisition

**Today** (from excerpts of `routes/requests.ts`, `requests/finder.ts`, `requests/worker.ts`, `requests/clients.ts`). Viewers request a
title; an administrator approves; approval can search Torznab indexers, reject sequels, wrong years and cam releases, rank for browser
playability and submit to debrid or qBittorrent. A worker polls every 2 seconds (`requests/worker.ts:149`). `MediaRequest`,
`RequestFollower` and `RequestEvent` hold the state.

**Best practice.** Overseerr and Jellyseerr: requests per movie or season, auto-approval and quotas per user, issue reports, notification
agents: <https://docs.overseerr.dev/>. Radarr and Sonarr: quality profiles with a cutoff, custom formats with scores, a blocklist and
retry with the next release; scoring conventions in <https://trash-guides.info/>. Prowlarr for indexer management:
<https://wiki.servarr.com/prowlarr>.

**Gap.** No per-season requests (blocked by B), no auto-approve or quotas, no quality profiles, no check for releases already cached on
the debrid service, no blocklist or retry, no notifications. Severity medium: requests work, but each one needs the administrator.

**Plan.** Quality profiles and scoring on the new parser (M, additive). Cached-first selection through the provider interface in D (S).
Blocklist and retry (S, additive). Auto-approve and quotas (S, additive). Notifications through one outbound interface with SMTP,
Discord, ntfy and generic webhook agents (M, additive; `nodemailer` is MIT). Per-season requests after B (M).

## D. Debrid layer

**Today.** `DebridProvider` (`server/src/providers/types.ts:65`) covers account info, unrestrict, add, status and list for Real-Debrid,
AllDebrid and Premiumize; TorBox is handled in `providers/account-library.ts`, outside that interface. Each caller sets its own timeout
(`types.ts:97`, `account-library.ts:93`). A 429 is turned into an error message (`account-library.ts:98`); there is no retry, backoff or
per-provider rate limit. Link health probes and repairs links (`link-health.ts`).

**Best practice.** One provider contract with cache checks and hash search, a shared HTTP client with jittered backoff and per-provider
limits, and unrestricted links cached until their real expiry, as Riven, Debrid Media Manager and Zurg do; rclone's pacer is the model for
backoff: <https://rclone.org/docs/#tpslimit-float>.

**Gap.** Medium: providers behave differently at the edges, rate limits surface as failures, and every play resolves a link again.

**Plan.** Widen the interface (cache check, select files, delete) and move TorBox behind it (M). Central client on the guarded client
from F, with retry, limits and a circuit breaker (M). Contract tests against recorded fixtures with secrets removed (M). Link cache with
expiry (S, one additive table or in memory).

## E. Users, access and identity

**Today.** Two roles in `User.role` (`schema.prisma:31`). JWT sessions with a version and a revocation list, HttpOnly cookie on the same
origin, a CSRF guard for cookie sessions (`auth/middleware.ts`, `csrfGuard`). Passwords: bcrypt, minimum 8 characters
(`routes/auth.ts:44`). Sign-in attempts are limited to 30 per 15 minutes per IP (`routes/auth.ts:36`). Invitations carry library access
and a viewing limit.

**Best practice.** OWASP ASVS 4.0 chapters 2 and 3: <https://owasp.org/www-project-application-security-verification-standard/>.
NIST 800-63B for passwords: <https://pages.nist.gov/800-63-3/sp800-63b.html>. OIDC as Authelia, Authentik and Keycloak provide it.
WebAuthn: <https://www.w3.org/TR/webauthn-2/>. Managed profiles with a PIN as in Plex Home.

**Gap.** No OIDC, 2FA or passkeys (medium). Throttling per IP only, lost on restart (medium). No device list for the viewer to revoke
(low). No managed profiles (medium for households). Two roles only (low).

**Plan.** Per-account and per-IP throttling with backoff (S, with F). Session list and revoke (S, additive). TOTP with recovery codes (M,
additive; `otplib` is MIT). OIDC with group mapping that respects the invitation policy (M, additive; `openid-client` is MIT). Passkeys
(M, additive; `@simplewebauthn/server` is MIT). Profiles with PIN and their own watch state (L, additive, after B). Permissions as a set
on the user, with the two roles kept as presets (M, additive).

## F. Security

**Today.**
- Headers: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` on the API (`server/src/http.ts`, `securityHeaders`) and on
  the gateway. No Content-Security-Policy, no `Permissions-Policy`.
- Outbound requests: 12 `fetch` call sites in 9 files, each with its own timeout and redirect rule. `link-health.ts:20` follows
  redirects. `convertibleUrl` (`transcode.ts:28`) blocks private addresses by matching the host text; a public name that resolves to a
  private address passes, and ffmpeg resolves it again by itself.
- Rate limiting: in memory, per IP (`util/rateLimit.ts`).
- Secrets: AES-256-GCM with a key from `DATA_ENCRYPTION_KEY` or derived from `JWT_SECRET` (`crypto.ts`). No rotation command.
- Docker socket: held only by the media manager helper with fixed container specifications (`infra/single-container/media-manager.cjs`,
  not read in full).
- Container: runs as `node` (`Dockerfile:58`), with a health check.
- No `SECURITY.md`, no threat model, no dependency audit or code scanning in CI.

**Best practice.** OWASP ASVS 4.0 Level 2; OWASP SSRF prevention:
<https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html>; CSP with nonces in Next.js:
<https://nextjs.org/docs/app/guides/content-security-policy>; Docker hardening:
<https://cheatsheetseries.owasp.org/cheatsheets/Docker_Security_Cheat_Sheet.html>; Sigstore: <https://docs.sigstore.dev/>;
SLSA: <https://slsa.dev/>.

**Gap.**
| Gap | Severity | Impact |
|---|---|---|
| No guarded outbound client; DNS rebinding possible on indexer, media-server and conversion URLs | high | An administrator-supplied or indexer-supplied URL can reach services on the server's network |
| No CSP | high | Script injected through metadata or release names would run with the viewer's session |
| In-memory, per-IP rate limiting | medium | Password guessing restarts after a restart and is not slowed per account |
| No key rotation | medium | A leaked key cannot be replaced without manual work |
| No supply-chain checks | medium | A vulnerable dependency or altered image is not noticed |
| No threat model or disclosure policy | medium | Reporters have nowhere to go |
| Authorisation is tested per feature, not for every route | medium | An ownership check missed on a new route would not be caught |

**Plan.** `SECURITY.md` and `docs/threat-model.md` (S). One outbound client: allow-list per purpose, private and link-local ranges
blocked with an explicit opt-in, DNS resolved once and pinned, size and time caps, no credentials across redirects; ffmpeg given the
pinned address (M). CSP with nonces in both web apps, tested in CI (M). Rate limiter on a SQLite table behind an interface that a Redis
store can implement later (S, additive). Key rotation command (S). Helper: an allow-list of Docker API endpoints and an audit entry per
action (S). A route inventory test that fails when a route with an id has no ownership test (M). Supply chain in J.

## G. Operations

**Today.** One image for `linux/amd64` (`publish-image.yml:59`, `publish-channel.yml:48`). SQLite only. `server/src/metrics.ts` exists
(48 lines, not read in full); no Prometheus endpoint was found. Backups, verified restore, update check and the Update button with
rollback exist. No PUID or PGID.

**Best practice.** linuxserver.io conventions for `PUID`, `PGID`, `TZ`, `UMASK`: <https://docs.linuxserver.io/general/understanding-puid-and-pgid/>.
Prometheus exposition: <https://prometheus.io/docs/instrumenting/writing_exporters/>.

**Gap.** No arm64 image (medium: no Raspberry Pi or ARM NAS). No PUID or PGID (medium: file ownership problems on NAS volumes). No
metrics endpoint (low). No scheduled backups with retention (medium). PostgreSQL (low for a household server).

**Plan.** Multi-arch build with a smoke test on both (M). PUID and PGID in the entrypoint, default unchanged for existing installs (S).
`/metrics` behind a token with `prom-client` (Apache-2.0) (S). Scheduled backups and a restore drill in CI (S). Update channels on the
button (S). Reverse-proxy examples (S). PostgreSQL last, and only if wanted: it doubles the migration and test surface (L).

## I. Quality engineering

**Today.** Vitest and supertest; Playwright journeys against production images on Playwright's Chromium, which has no H.264 or AAC
decoder; upgrade tests from every schema checkpoint; an installer test with a Docker stub. No coverage report. Real-ffmpeg tests did not
run in CI until v0.23.2.

**Gap.** No coverage numbers (low). No contract tests for providers and indexers (medium). No load test (low). Playback was not tested
with real decoders (high, closed in part by v0.23.2).

**Plan.** Coverage reported, then a floor raised in steps to 85% (S). Contract fixtures with D (M). Playback matrix with A. A load test
recorded in `docs/performance.md` (S).

## J. Release engineering

**Plan.** Pin actions by commit SHA with Dependabot grouped updates (S). `npm audit` or OSV-Scanner and CodeQL (S). SBOM with Syft and

## K. Code health and architecture

**Today.** 122 files are kept identical by `scripts/sync-shared.cjs` and `shared-manifest.json`. Route files make 69 direct Prisma
calls. 187 lines in `server/src` are longer than 200 characters. No ESLint or Prettier; `npm run lint` is `tsc --noEmit`. Background
work runs on seven separate timers (`metadata/automation.ts:268`, `requests/worker.ts:149`, `link-health.ts:111`,
`account-library.ts:177` and others). Configuration is read from `process.env` in `config.ts` and in individual modules without
validation. `CONTRIBUTING.md` asks for Node 22; CI and the image use Node 24.

**Plan.** npm workspaces with `packages/core`, `packages/db`, `packages/ui`, `packages/api-types`, moved in stages with no behaviour
change, then the manifest and script removed (L). OpenAPI 3.1 from the Zod schemas with `@asteasolutions/zod-to-openapi` (MIT) and a
generated client (M). ESLint and Prettier in one mechanical PR (M, large diff, no behaviour change). One job runner with leases and
retries (M, additive table). Validated configuration with a generated table (S). Services and repositories introduced per module as
each is touched, not in one rewrite.
